# 跨客户端云同步真写测试需求

## 1. 问题与目标

当前微信开发者工具默认处于 `cloudReadOnly=true`。这能保护生产云数据，但只能验证单客户端本地学习闭环，不能验证开发者工具、手机真机、电脑版微信之间的真实云写、拉取、冲突合并和失败恢复。

本需求的目标是建立一套可重复执行的跨客户端真写测试能力。教师“张张张123”（`teacher_id=oPLFQ1-8lLKRJVX7qukRc4ooeKgs`）已由用户明确确认为专用测试账号，该教师名下数据允许用于测试；其他教师及其学生数据必须零接触、零覆盖、零删除。

## 2. 范围

包含：

- 微信开发者工具、手机真机和第二客户端之间的双向同步测试。
- `students`、`learning_records`、`learning_progress`、`word_mastery`、`preview_state`、`student_statistics`、`wordbook_statistics` 等同步链路。
- 每日新学、抗遗忘复习、首页/记录/统计/词书页面的一致性验证。
- 离线、重试、重复启动、并发修改和旧格式数据兼容验证。
- 测试运行前后的教师作用域与测试学生作用域数据核对。

不包含：

- 修改、迁移、修复或删除“张张张123”之外任何教师的数据。
- 删除现有测试学生或其历史记录。
- 未经明确确认创建收费 CloudBase 环境。
- 自动清理生产集合或生产客户端缓存。
- 与同步测试无关的页面、视觉或业务重构。

## 3. 数据安全硬约束

1. 真写测试可以使用现有 CloudBase 环境和正式业务集合，以确保同步代码、权限和云函数与正式版一致，但所有写入必须同时受允许的 `teacher_id` 和专用 E2E 学生 ID 约束。
2. 测试客户端不得读取、写入或删除其他教师作用域中的文档。
3. 默认新建一个名称和 ID 均带 E2E 标识的专用学生；现有测试学生允许读取和回归，但不用于破坏性测试。
4. 测试身份、学生 ID、运行 ID 和文档 ID 必须带有明确的 E2E 标识，并可追溯到单次测试。
5. 正式版 `envVersion=release` 必须忽略所有测试启动参数，并继续使用现有生产环境和生产集合。
6. 测试模式必须采用至少两个独立开关，避免误触发；单独一个普通 query 参数不得启用测试云写。
7. 任何隔离条件不满足时，系统必须回退为云端只读，而不是写入生产集合。
8. 删除测试数据属于独立的破坏性操作，必须先列出精确目标并取得确认；默认保留专用 E2E 学生及测试数据用于持续回归和审计。

## 4. 用户故事

1. 作为现有用户，我希望跨客户端测试严格限制在“张张张123”测试教师和专用 E2E 学生范围内。
2. 作为测试人员，我希望在开发者工具完成学习后，手机真机能够从隔离云数据中恢复完全一致的状态。
3. 作为测试人员，我希望手机完成复习后，第二客户端能够拉取并合并结果，且不会生成重复记录。
4. 作为维护者，我希望每次测试都有唯一运行 ID、明确的数据范围和生产集合前后指纹证据。
5. 作为发布负责人，我希望正式版无法被普通启动参数切换到测试数据源。

## 5. 验收标准

### R1：默认安全

当小程序没有满足完整测试激活条件时，系统必须保持现有生产行为；当运行环境为开发者工具时，系统必须保持云端只读。

### R2：正式版封锁

当 `envVersion=release` 时，无论启动参数为何，系统都不得启用 E2E 测试数据源或测试云写。

### R3：隔离激活

当非正式版客户端同时提供有效测试开关、合法运行 ID、允许的教师 ID 和专用学生 ID 时，系统才可以启用 E2E 真写模式；任一条件缺失时必须回退为只读。

### R4：教师和学生作用域隔离

当 E2E 模式启用时，所有业务数据写入必须同时匹配允许的测试教师和专用 E2E 学生；任何业务路径尝试写入其他教师或学生时，系统必须拒绝并记录错误。

### R5：本地缓存隔离

当 E2E 模式启用时，开发者工具应使用独立测试项目缓存或专用学生作用域；不得清空或覆盖当前开发者工具中其他学生的 `learningRecords`、`learningProgress`、`wordMastery` 等数据。

### R6：可追溯性

当测试客户端创建云文档时，每条文档必须包含测试运行 ID、测试身份、客户端标识和创建/更新时间；查询单次运行时不得混入其他运行或生产文档。

### R7：A 到 B 同步

当客户端 A 完成 20 词新学闭环并成功上传后，客户端 B 冷启动并拉取同一测试运行数据时，首页、学习记录、统计、词书和本地明细必须与云端及客户端 A 一致。

### R8：B 到 A 同步

当客户端 B 完成到期抗遗忘复习并成功上传后，客户端 A 重新启动或主动同步时，系统必须合并相同批次并更新 `reviewCount`、时间线和下次复习时间，不得重复生成学习记录。

### R9：失败恢复

当客户端在断网或云写失败时产生数据，系统必须保留本地记录并建立待同步任务；当网络恢复且云端拉取成功后，系统必须重试上传并清空已成功任务。

### R10：并发与防回退

当两个客户端先后修改同一单词时，系统必须按照既定合并规则保留更新的复习进度，不得用旧客户端状态覆盖更新的云端状态。

### R11：生产数据证明

当一次 E2E 测试结束时，系统必须重新只读计算教师与学生作用域的数据；除专用 E2E 学生外，其他学生的文档数量与更新时间必须保持不变。任何变化都必须逐条说明来源。

### R12：回滚

当测试配置或代码出现异常时，维护者必须能够回到测试前 Git 提交，并且不需要恢复任何生产用户数据。
