## 2. 推荐唯一方案：共享环境内专用测试资源，待批准及验证
目标 cloudbase-4gafzdch60ad597b。沿用同一AppID/真实OfferID，使用独立TEST商品和独立测试集合/函数/权限返回，正式应用不接测试结果。
新CloudBase环境并非支付协议必需；支付signData与查单参数的env是支付现网/沙箱，不是CloudBase EnvId。新环境仍需关联AppID、凭据及通知配置，无法替代真实支付账号配置核验。
优点：不新增环境基础套餐；复用现有AppID与云开发关系，减少跨环境登录接线。代价：共享配额、运行权限和平台回调配置仍有风险，必须完成以下条件，不能只靠昵称、数据标签或前端隐藏。
- 新函数使用固定测试EnvId、固定白名单和固定集合映射；禁止请求传collection/env/teacherId/amount/duration。所有学生写入也只到独立测试集合。
- 平台商品按账号分别白名单，Android不能购买iOS专用商品，反之亦然；普通用户一律拒绝。订单/签名/授权/管理员/补偿各入口都限定测试身份与测试批次。
- 专用集合客户端全部禁读写，由受控函数按归属返回；验证既有云函数不存在允许普通用户传集合名写入测试集合的通道。只检查必要写入口，不全仓审计。
- 通知只处理已存在于测试集合的原订单，校验应用、商品、金额、支付环境和交易绑定；不能凭回调临时创建订单或为名单外老师建权益。
- 管理员入口独立认证；不与小程序身份入口混用HTTP来源，防实例复用残留身份；内部补偿不开放客户端action，并限定测试订单集合。
- 用确定性文档ID/真实事务保护订单、平台交易占用、名额与grant。每份测试数据关联固定批次；批次不是唯一安全边界。
- 先部署默认禁购版本，完成普通用户拒绝、客户端直写拒绝、跨账号订单拒绝、测试批次越界拒绝等云端测试后，才启用两个受限商品。
- 官方通知地址/订阅如已有其他消费者，不覆盖或切断现有功能；先只读核清共存方式。此项未知时停止通知配置，不擅自改原地址。

方案是建议，不是已实现的安全证明。现有Stage3仓库集合名尚未映射到测试前缀；管理员/令牌/权限持久化适配尚未接线，不能原样部署。
费用：不新建环境、不默认升级现有套餐；仍会消耗现有数据库/函数/网关/日志配额，超额费用、额度和退款手续费以授权部署前当前平台账单/配置核实，不承诺零费用。发现需升级/购买时停下确认。
