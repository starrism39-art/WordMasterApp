# 抗遗忘与跨设备统计一致性需求

## 范围

本次改动覆盖抗遗忘复习列表、学生/词书上下文、客户端云同步顺序、首页/词书/记录/统计/教师端统计口径，以及为真实数据测试提供的云端只读保护。

不修改云数据库结构，不批量修复或覆盖真实云端数据，不改变词库内容，不做无关 UI 重构。

## 用户故事

1. 作为学生或教师，我希望抗遗忘列表只显示当前学生、当前词书中已经到期的复习词，避免串学生、串词书或把未来任务误认为待复习。
2. 作为学生，我希望未掌握复习与已掌握到期巩固有明确区分，并在复习后得到一致的状态、记录和统计。
3. 作为同一账号的多设备用户，我希望重新进入小程序后先安全合并云端最新数据，再展示同一套学生、词书和统计口径。
4. 作为测试负责人，我希望微信开发者工具中的验证默认禁止真实云端写入，除非明确选择允许写入。

## 验收标准

1. 当抗遗忘页面生成列表时，系统应只读取当前学生和当前词书作用域内的 `wordMastery`。
2. 当记录显式携带的学生或词书标识与当前上下文不一致时，系统应排除该记录。
3. 当复习时间晚于当天时，系统应不把该词显示为当前待复习任务。
4. 当单词未掌握且复习到期时，系统应把它标记为“未掌握复习”。
5. 当单词已掌握、保留抗遗忘种子且复习到期时，系统应把它标记为“巩固复习”。
6. 当记录已完成五轮或没有有效复习种子时，系统应排除该记录。
7. 当旧数据缺少新字段时，系统应使用现有状态、时间和容器作用域降级判断，不删除原记录。
8. 当小程序使用缓存 OpenID 启动时，系统应先拉取并安全合并云端数据，再重试未完成上传或补推本地进度。
9. 当页面计算当前词书统计时，系统应统一从当前学生、当前词书的原始掌握记录和学习记录派生，不使用其他词书的缓存值。
10. 当运行环境为微信开发者工具时，系统应默认跳过所有自动云端写入；云端读取和本地隔离验证仍可执行。
11. 当任一同步步骤失败时，系统应保留本地数据并降级展示，不清空、不覆盖、不批量修复真实云端数据。
